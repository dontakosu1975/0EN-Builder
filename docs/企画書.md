# 0EN Builder 企画書

## 1. 企画概要

0EN Builderは、HTMLやCSSを知らない人でもWebページを作成でき、使い込むにつれてより高度なWeb制作へ進めるVisual Web Builderを目指す。

現在のWeb制作では、文字色を変える、文字サイズを変える、余白を調整するといった基本的な装飾であってもCSSが必要になる。かつてのホームページ作成ソフトでは利用者が「文字を赤くする」と考えるだけで済んだ操作が、現在はHTMLとCSSという技術的な境界を意識しなければならない場合が多い。

0EN Builderでは、この境界をGUIによって隠す。

利用者はHTML/CSSを書くのではなく、「何をどう見せたいか」を操作する。0EN Builderがその操作をHTML/CSSへ翻訳する。

## 2. 解決したい課題

Web制作の初心者にとって、HTMLとCSSは制作を始める前の学習コストになりやすい。

たとえば「文字をオレンジにしたい」という単純な目的でも、実装上は `color`、style属性、CSSセレクタ等の知識へつながっていく。

0EN Builderは、利用者にこの内部事情を要求しない。

利用者から見える操作：

`文字を選ぶ → 色を選ぶ → オレンジになる`

内部処理：

`GUI操作 → 状態更新 → CSS生成 → プレビュー更新`

HTML/CSSはなくすのではなく、必要になるまで見せない。

## 3. プロダクトの考え方

### 初めて触った人を、コードで止めない

Web制作経験がない利用者でも、画面を見ながら触ることで簡単なLPを完成させられることを最優先する。

専門用語を覚えてから制作を始めるのではなく、制作を始めた後で必要に応じて知識を深められる設計とする。

### 慣れた人を、簡単機能だけで止めない

初心者向けの簡単さを維持しながら、詳細設定やコードへ段階的にアクセスできる構造とする。

想定レベル：

- かんたん：色、大きさ、位置、余白などを日常語で操作
- 詳細：px等の数値や細かな設定を操作
- コード：生成されたHTML/CSSを直接確認・編集

同じページ・同じ内部データを、利用者の習熟度に応じて異なる粒度で操作できる状態を目指す。

## 4. UIの基本構造

既存のVisual Web Builderで確立されている操作構造を参考にする。

- 左ペイン：追加できるもの
- 中央ペイン：ページ本体／ライブプレビュー
- 右ペイン：選択中のものの設定

重要なのは画面構造そのものではなく、右ペイン等でCSS用語をそのまま利用者へ要求しないことにある。

例：

- `text-align:center` → 「中央にする」
- `padding` → 「内側の余白」または「まわりを広げる」
- `border-radius` → 「角を丸くする」
- `display:flex` → 将来的には「横に並べる」等の操作として提供

## 5. 技術上の基本思想

基本フローは以下とする。

`GUI操作 → 内部モデル → HTML/CSS生成 → ライブプレビュー`

内部モデルを持つことで、GUIと生成コードを直接べったり結びつけず、将来的な要素追加や複雑なレイアウトへ拡張しやすくする。

ただしPoC段階では過度な抽象化を避け、必要最小限のモデルから始める。

出力は可能な限り標準的なHTML/CSSとし、0EN Builderでしか利用できない独自形式へのロックインを避ける。

これにより、将来的には0ENでの公開だけでなく、別サーバーへの配置、CMSへの貼り付け、HTMLとしての保存等も視野に入れる。

## 6. PoC 01

### 目的

「HTML/CSSを知らなくても、GUIだけで基本的なWeb表現を作れる」という中核思想を検証する。

### 実装対象

まず一つのコンテンツを編集対象として、以下の操作をGUI化する。

- テキスト内容
- 文字色
- 背景色
- 文字サイズ
- 太字
- 左寄せ／中央／右寄せ
- 行間
- padding
- margin
- 幅
- border
- border-radius

変更結果は即座に中央プレビューへ反映する。

生成されたHTML/CSSを確認できる機能も用意する。ただし通常操作ではコードを見なくても完結できるものとする。

### PoCでやらないこと

初期段階では以下を実装対象外とする。

- 複雑なDIV構造
- テーブル
- 複雑なカラム
- 本格的なドラッグ＆ドロップ
- 複数ページ
- ログイン
- バックエンド
- データベース
- 0EN本体との連携

最初からWeb Builder全体を作ろうとせず、CSSの基本操作をGUIへ翻訳する体験の検証に集中する。

## 7. 成功条件

PoC 01の評価基準は機能数ではない。

**Webサイトを作ったことがない人が、説明書を読まず、HTML/CSSを意識せずに簡単なLPを作り始められること。**

さらに、操作結果として生成されたHTML/CSSが通常のWeb技術として扱えることを確認する。

## 8. 発展ロードマップ

PoC 01の結果を見ながら、以下の順序を基本として拡張する。

### Phase 1：基本装飾
文字、色、サイズ、配置、背景、余白、枠線など。

### Phase 2：基本要素
画像、リンク、ボタン、区切り等を追加。

### Phase 3：複数要素
複数の要素をページ内に配置し、順序変更や複製・削除を可能にする。

### Phase 4：構造
セクション、囲み、DIV等の概念を初心者向けGUIへ翻訳する。

### Phase 5：レイアウト
Flex、横並び、2列・3列等を「レイアウト」として視覚的に扱う。

### Phase 6：レスポンシブ
PC／スマートフォンでの並び方や表示方法を、CSSを直接意識せず設定できるようにする。

### Phase 7：サイト制作
複数ページ、ヘッダー、ナビゲーション、フッター、共通スタイル等へ拡張する。

### Phase 8：高度なWeb表現
iframe、フォーム、動画、地図、アニメーション、詳細CSS等へ対象を広げる。

## 9. Scratch的発想

将来的には、Webページを構成する要素やレイアウトを組み合わせる操作にScratch的な考え方を取り入れる。

ただし、JavaScript等のプログラムロジックをブロック化することを主目的にはしない。

対象はあくまでWebページの構造・配置・装飾である。

例：

`セクション → 2列 → 左に画像 / 右に文章`

という構造を、HTMLのネストやFlexboxを知らなくても組み立てられるようにする。

## 10. 公開・OSS方針

0EN BuilderはGitHub上で公開し、外部から内容を確認でき、改造・再配布可能な形で開発する方向とする。

既存OSSをベースまたは一部利用する場合は、採用時点でライセンス条件を確認し、その条件に従う。

特定のOSSを初期段階から前提にはしない。PoC 01は小さく独自実装し、必要性が明確になった時点で既存エンジンやライブラリの採用を判断する。

## 11. 位置づけ

0EN Builderは単に「CSSを簡単に設定するツール」ではない。

目指すのは、HTML/CSSという技術的な境界を利用者から遠ざけながら、最終的にはWeb標準の自由度へ到達できる制作環境である。

**最初は簡単なLP。触っていくうちに、もっと凝ったホームページへ。**

この段階的な成長を、同じエディタの中で実現する。
